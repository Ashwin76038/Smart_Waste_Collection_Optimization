# Exact Power BI Desktop build guide

> **30 September 2026 update:** Actual PBIX delivered and Desktop-tested. See [Desktop delivery](DESKTOP_DELIVERY.md). Original offline handoff below is historical; its no-PBIX status is superseded. Dedicated measure table is named `KPI Measures`.

**Execution status:** Power BI Desktop was not installed or available to operate in this workspace, and no PBIX was produced. These are exact manual steps for a later Windows Desktop session. The local CSVs and DAX definitions are ready. Keep the report local until a separate review authorizes publication.

1. Open Power BI Desktop and create a blank report. Under *File → Options and settings → Options → Current File → Data Load*, turn off automatic date/time tables. Set locale/date interpretation to English (India) or explicitly parse ISO dates in Power Query. Save the work-in-progress as `Smart_Waste_Chennai_Coimbatore.pbix` **inside this project’s `12_powerbi` directory**.
2. Use *Get data → Text/CSV* and import the 14 files in `12_powerbi/phase5_model/` whose names begin `dim_` or `fact_`. Do not import `qa_receipt.json`, `kpi_reconciliation.csv`, `ward_audit_candidates.csv`, `threshold_tradeoffs.csv`, the 6.57M sensor fact or earlier `two_city_data` exports. Choose Import mode. Keep one query/table per file; do not merge them into a flat table.
3. In Power Query, assign Text to all `_key`, `city_id`, labels, status, model and source fields. Assign Date to `service_date`, `issue_date`, `target_date`; Date/Time to `attempted_at_utc` if used. Assign Whole Number to count/rank/tier fields, True/False to flags, Decimal Number to fill, litres, kg, km, MAE, utilization and coordinates. Treat blank route outputs for infeasible scenarios as null. Apply changes. Inspect row counts against [qa_receipt.json](phase5_model/qa_receipt.json): dimensions 2/365/300/1500/18 and facts 730/547500/109135/322675/1500/18/72/30/8 in the order documented in [PHASE5_MODEL.md](PHASE5_MODEL.md).
4. In Model view, delete any auto-created relationships. Add the **16 active one-to-many, single-direction** links shown in [PHASE5_MODEL.md](PHASE5_MODEL.md): `dim_city[city_id] → dim_bin`, `dim_zone`, `dim_scenario`, `fact_city_day`, `fact_forecast_score`; `dim_date[service_date] → fact_city_day`, `fact_bin_day`, `fact_zone_day`, `fact_collection_attempt`; `dim_bin[bin_key] → fact_bin_day`, `fact_collection_attempt`, `fact_dispatch_snapshot`; `dim_zone[zone_key] → fact_zone_day`; `dim_scenario[scenario_key] → fact_route_scenario`, `fact_truck_route`, `fact_counterfactual`. Never relate fact tables to each other or turn on bidirectional filtering. Mark `dim_date` as the date table using `service_date`.
5. Create a small `Measures` table through *Home → Enter data* with one dummy row. Hide its dummy column. For every named formula in [PHASE5_MEASURES.dax](PHASE5_MEASURES.dax), choose *New measure* in that table and paste the definition. DAX files are plain text; Desktop does not automatically import this file as measures. Format counts as whole numbers; kg/tonnes, litres, km and INR with appropriate units. For measures ending `%` but already multiplied by 100, format as a **decimal number** with one or two decimals and put `%` in the measure title; Power BI's Percent format would multiply by 100 again. Keep forecast MAE in percentage points.
6. Import [phase5_theme.json](phase5_theme.json) through *View → Themes → Browse for themes*. Use a 16:9 canvas, consistent 12–24 px spacing, clear title bars, navigation buttons and a small scope/source note on every page. Create the five pages in [PHASE5_WIREFRAMES.md](PHASE5_WIREFRAMES.md). Set report/page slicers: city throughout; 2026 date range only for historical pages 1–3; single-select city and scenario on route page (default `base_3_trucks`); single-select city, score filters (`test`, `known_bins`) on planning page. Sync city slicer where useful, but allow Overview both-city comparison. The route page must show a single city.
7. For the geography page, use a Power BI map visual with `dim_bin[latitude]`, `dim_bin[longitude]` and `Overflow Bin-Days` as bubble size, with `bin_key`, `ward_label`, `capacity_l` and data origin in tooltip. Set Latitude/Longitude data categories. The separate [Chennai geography](../14_outputs/maps/phase4_geospatial.html), [Coimbatore geography](../cities/CBE/14_outputs/maps/phase4_geospatial.html) and [Coimbatore priority](../cities/CBE/14_outputs/maps/phase4_priority.html) HTML outputs can be opened locally for fuller outlines/queues. Use one city map extent at a time.
8. In route visuals, use `dim_scenario[scenario]` as a single-select slicer and `dim_scenario[status]` as a visible status field. Base route cards should show Chennai **57.3439 → 45.4983 km** or Coimbatore **38.4570 → 27.9743 km**. Fuel-price-only alternatives repeat the same physical route; present them only as cost sensitivity. Distances, prices and spills are modeled. Avoid annualizing one dispatch.
9. Reconcile Desktop cards with [kpi_reconciliation.csv](phase5_model/kpi_reconciliation.csv) for both city selections. Check [qa_receipt.json](phase5_model/qa_receipt.json) for 52 passed SQL/Python values. Specifically verify fill using weighted numerator/denominator, overflow slot rate using scheduled slots, early service using completed attempts, route savings using one feasible scenario, and the 0.37/0.17 kg float-precision difference between collection-attempt and daily totals. If a card differs beyond the listed tolerance, inspect relationship direction, wrong grain, duplicate imported source or percentage formatting before accepting it.
10. Review all pages at 100% zoom and narrow window width. Confirm readable tooltips, no clipped chart labels, correct city/date/snapshot scope, feasible-only route cards, negative spill values visible, and synthetic/proxy language on exported page images. Save the PBIX inside `12_powerbi/` only after this review. Record its filename, row counts and visual QA in `PROJECT_STATE.md` in the later Desktop session; the current handoff does not claim these steps occurred.
