# Acceptance criteria

## Phase 1
All requested directories exist; 23 roadmap workstreams each contain eight requested fields; required research documents and catalog are readable; every source has a URL, access date and verification caveat; all tables have grain/PK/FK/cardinality/units; no generated event dataset; no cloud setup; PROJECT_STATE accurately states limitations.

## Eventual portfolio evidence
| Capability | Required evidence |
|---|---|
| Business | Decision charter, KPI formulas, stakeholder actions and service guardrails |
| Acquisition | Actual source snapshots/manifests, hashes, license and coverage evidence |
| Excel | Recalculating workbook with PivotTables, XLOOKUP, COUNTIFS, SUMIFS and validation |
| SQL | Reviewed analytical queries including windows, CTEs, ranking, joins and reconciled marts |
| Python/scale | Reproducible generator/ETL, Parquet and measured multi-million-row query benchmarks |
| Statistics | Independent units, uncertainty, justified hypotheses, assumptions and effect sizes |
| Geospatial | Verified CRS, directed road paths, coverage gaps and attribution |
| Forecasting | Naive comparison, rolling time/spatial holdouts, leakage checks and model card |
| Optimization | Constraints, status, independent route evaluator and service-adjusted comparison |
| Economics | Cost bridge with dated INR inputs, sensitivity, fixed/variable separation |
| Cloud | Optional no-billing Sandbox SQL parity and dated evidence; limitation disclosed if blocked |
| Power BI | Reconciled model, usable pages, filters, QA and visible origin labels |
| Testing | Meaningful pytest failures/successes and cross-tool reconciliation |
| Documentation/Git | Source traceability, setup lock, genuine history, walkthrough and limitations |

A 9/10 hiring-quality outcome is an aspiration, not a score that the scaffold earns. Final quality depends on evidence and honest decisions, including reporting when a method does not improve service/cost.
