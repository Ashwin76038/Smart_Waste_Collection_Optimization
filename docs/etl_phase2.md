# Phase 2 local pipeline and provenance

The executable stages live in `06_python/scripts/`. Run from the project root. Original downloads in `03_data/raw/Sxx/retrieval-date/` are immutable; the acquisition script verifies an existing snapshot hash and never edits it. Each acquired payload has a source URL, retrieval time, byte count and SHA256 in `02_research/acquisition_manifest.csv`. `acquisition_attempts.csv` records failures. A source catalog row with `local_filename` lists its snapshots. The Chennai Smart Cities catalog (S04) had no downloadable resource; its saved HTML is metadata, not a bin inventory. Census India TLS validation failed in this environment; the official workbook/PDF download used an explicitly logged certificate exception. Redistribution terms still require review.

1. `python 06_python/scripts/acquire_sources.py --large` obtains listed official files and the dated Southern Zone OSM PBF. The PBF is regional because the provider's snapshot is immutable; it is not the final routing graph.
2. `python 06_python/scripts/prepare_real_sources.py official` reads official ward polygons, native 2011 Census rows and the 2025 NASA weather grid, producing separate typed Parquet tables. Ward and Census keys are **not** joined.
3. `python 06_python/scripts/prepare_real_sources.py osm` extracts mapped road nodes, road segments and POI nodes inside GCC wards. The source is OSM contributors, via Geofabrik. Tags are incomplete and segments are not yet a restriction-aware truck graph.
4. `python 06_python/scripts/build_synthetic_bins.py` creates five hypothetical bins in each of 199 covered wards on distinct real road nodes, plus five extra in ward 032 because ward 200 has no eligible mapped road node in the extract. Road-node coordinates are real; bin deployment, capacity and demand factors are synthetic assumptions. It records the OSM node ID for audit.
5. `python 06_python/scripts/generate_operations.py 365` simulates 1,000 bins, 12 two-hour slots/day and 365 days in 2026. CSV files are synthetic source artifacts, with latent truth columns; no real IoT record is claimed.
6. `python 06_python/scripts/convert_events.py` validates each monthly CSV, writes full interim Parquet, then publishes an observed-only fact in `03_data/processed/fact_bin_readings/year=2026/month=MM` and isolates latent simulation truth in `03_data/synthetic/truth`. Conversion is month bounded in memory and Zstandard compressed.
7. `python 06_python/scripts/build_duckdb.py` creates persisted DuckDB tables for daily bins/zones, collections, route planning proxies and vehicle days, plus a Parquet-backed fact view. The DB stores no redundant copy of 4.38M readings.
8. `python 06_python/scripts/profile_data.py` profiles important datasets and writes `14_outputs/reports/data_profile.json` and `data_quality_report.md`.
9. `python 06_python/scripts/benchmark_large_data.py` compares equivalent January scans with Pandas full load, Pandas chunks, DuckDB CSV and DuckDB Parquet in fresh worker processes.
10. Run `python -m pytest 13_testing -q -p no:cacheprovider` with project dependencies available. The foundation validator also remains available.

Synthetic generator assumptions are in `config/simulation_assumptions.md` and `config/assumption_register.csv`. The fixed seed is 20260923. Each two-hour slot adds nonnegative Gamma arrivals. Bin and ward effects, intraday and weekly schedules, seasonal modulation, 4% missed due collections, 3% partial successful collections, sensor noise, stuck readings and missing messages are scenario parameters. The collection policy is a **generator assumption**, not an optimized policy or documented city schedule.

The raw synthetic CSV keeps `arrivals_l_true`, `inventory_l_true`, `overflow_l_true`, `removed_l_true` so mass balance can be tested. These fields are removed from the processed reading fact and held in a separate truth Parquet path. Forecasting code in a later phase must not train on truth. `data_origin=synthetic` is present on every operational row. Official and real geographic tables keep distinct origin labels.

Route and vehicle daily tables in this phase are schematic planning proxies. Bins are assigned to one of 50 hypothetical vehicles by ward number. Assumed route distance is 5 km plus 0.35 km per successful stop; assumed diesel economy is 4.5 km/L. These values are **not** actual road routes, measured fuel, cost savings or a city fleet roster. Phase 4 optimization must replace the proxy with directed network paths and verified constraints before operational conclusions.

DuckDB uses a 4 GB memory limit and project-local temp directory. Filters on `year`/`month` hive partitions and selected columns demonstrate avoiding scans of unrelated data. The query plan is saved in `14_outputs/reports/duckdb_query_plan.txt`; do not infer performance from plan shape alone.
